# نظام إدارة مكتب الأبحاث العلمية
**Scientific Research Office Management System**

نظام ويب متكامل لإدارة دورة حياة البحث العلمي في الجامعات ومكاتب البحث العلمي: من تقديم البحث، مروراً بالمراجعة الإدارية والتحكيم العلمي السري وطلبات التعديل، وصولاً إلى القبول والنشر والأرشفة، مع تقارير قابلة للتصدير وصلاحيات دقيقة مفروضة على الخادم.

> **العلامة المائية:** تظهر العبارة «**عمل الطالبة رهف إبراهيم والطالبة أسيل خالد**» في خلفية جميع صفحات النظام، وفي ملفات PDF والتقارير المصدرة والمطبوعة، وتُختم بها ملفات PDF عند تنزيلها.

## التقنيات المستخدمة

| المجال | التقنية |
|---|---|
| الواجهة والخادم | Next.js 16 (App Router، Server Components، Server Actions) + TypeScript |
| التصميم | Tailwind CSS 4 + مكونات بنمط shadcn/ui (Radix UI) + أيقونات lucide |
| الخط | Cairo (مستضاف محلياً عبر ‎@fontsource — لا يعتمد على الإنترنت) |
| قاعدة البيانات | PostgreSQL + Prisma ORM 7 (محوّل ‎@prisma/adapter-pg) |
| المصادقة | جلسات آمنة مخزنة في قاعدة البيانات + bcrypt لتشفير كلمات المرور |
| التحقق من المدخلات | Zod 4 |
| الرسوم البيانية | Recharts |
| PDF | Chromium (playwright-core) لتوليد PDF عربي سليم + pdf-lib لختم الملفات |
| Excel | ExcelJS |
| فحص الملفات | file-type (فحص التوقيع الحقيقي للملف) |

## المتطلبات
- **Node.js 20.9+** (تم الاختبار على Node 22)
- **PostgreSQL 14+** (أو Docker لتشغيلها عبر `docker compose`)
- **Chromium** لتصدير PDF (اختياري؛ عند غيابه يعرض النظام نسخة قابلة للطباعة والحفظ كـ PDF من المتصفح)
- **pg_dump** للنسخ الاحتياطي من لوحة الإعدادات (يأتي مع عميل PostgreSQL)

## التثبيت والتشغيل

```bash
# 1) تثبيت المكتبات (يولّد Prisma Client تلقائياً)
npm install

# 2) إعداد متغيرات البيئة
cp .env.example .env
# ثم عدّل DATABASE_URL و SESSION_SECRET ...

# 3) (اختياري) تشغيل PostgreSQL عبر Docker
docker compose up -d

# 4) إنشاء الجداول
npm run db:migrate

# 5) تهيئة البيانات
npm run db:seed          # الأدوار والصلاحيات + بيانات تجريبية (للتطوير فقط)
# أو
npm run db:seed:base     # الأدوار والصلاحيات وحساب المدير فقط (للإنتاج)

# 6) (لتصدير PDF) تثبيت Chromium إن لم يكن متوفراً
npx playwright install chromium

# 7) التشغيل
npm run dev              # وضع التطوير
# أو
npm run build && npm start   # وضع الإنتاج
```

ثم افتح: **http://localhost:3000**

## بيانات الدخول التجريبية
> ⚠️ **بيانات تجريبية لبيئة التطوير فقط** — تُنشأ بالأمر `npm run db:seed` ويرفض الأمر إنشاءها عند `NODE_ENV=production`. جميع الأبحاث التجريبية موسومة بـ «[بيانات تجريبية]» ويظهر تنبيه بذلك في لوحة التحكم.

كلمة المرور لجميع الحسابات: **`Password@123`**

| الدور | البريد الإلكتروني |
|---|---|
| مدير النظام | `admin@research.local` |
| مدير مكتب الأبحاث العلمية | `manager@research.local` |
| الموظف الإداري | `staff@research.local` |
| باحث | `researcher@research.local` (وأيضاً researcher2، researcher3) |
| محكم علمي | `reviewer@research.local` (وأيضاً reviewer2 … reviewer4) |

**غيّر كلمة مرور المدير فوراً في أي بيئة حقيقية** (من صفحة الملف الشخصي).

## الأدوار والصلاحيات
نظام RBAC كامل: جداول `roles` و `permissions` و `role_permissions`، ويمكن تعديل صلاحيات الأدوار من الواجهة.

| الدور | أبرز الصلاحيات الافتراضية |
|---|---|
| **مدير النظام** | جميع الصلاحيات (غير قابلة للتقليص): المستخدمون، الصلاحيات، الإعدادات، النسخ الاحتياطي، كل التقارير |
| **مدير مكتب الأبحاث** | إدارة الأبحاث، متابعة الطلبات، تعيين المحكمين، الاطلاع على التقييمات، اعتماد القرارات (قبول/رفض/نشر)، التقارير، الهيكل الأكاديمي |
| **الموظف الإداري** | تسجيل الأبحاث، تنظيم الملفات، المراجعة الإدارية ومتابعة الحالة، إدارة الباحثين، التقارير |
| **الباحث** | إنشاء بحث، رفع الملفات، متابعة الحالة، استقبال الملاحظات، إرسال النسخ المعدلة، الأرشيف (المنشور فقط) |
| **المحكم العلمي** | الاطلاع على الأبحاث المسندة إليه فقط، كتابة التقييم، تقديم قرار التحكيم |

**الفرض على الخادم:** كل صفحة تستدعي `requirePermission`، وكل Server Action تستدعي `assertPermission`/فحص الوصول، وكل واجهة API تتحقق من الجلسة والصلاحية وصلاحية الوصول للبحث المحدد (`getPaperAccess`). إخفاء الأزرار في الواجهة هو تحسين للتجربة فقط.

**سرية التحكيم:** الدرجات والتوصيات والملاحظات السرية وتقارير المحكمين لا تظهر إلا لمن يملك `reviews.view_all`. يرى الباحث «الملاحظات للباحث» فقط دون هوية المحكم، ويخفي التحكيم المعمّى أسماء الباحثين عن المحكمين (قابل للتعطيل من الإعدادات).

## دورة حياة البحث

```
مسودة ← تم التقديم ← قيد المراجعة الإدارية ← قيد التحكيم العلمي ← مقبول ← منشور ← مؤرشف
                          ↓                         ↓            ↘ مرفوض ← مؤرشف
                    يحتاج إلى تعديلات ←──────────────┘
                          ↓ (الباحث يرسل نسخة معدلة)
                    تمت إعادة التقديم ← (مراجعة / جولة تحكيم جديدة / قرار)
```
- الانتقالات معرّفة في `src/lib/workflow.ts` ولكل انتقال صلاحية مطلوبة.
- تعيين محكم لبحث مقدم ينقله تلقائياً إلى «قيد التحكيم العلمي».
- كل تغيير يُسجَّل في سجل الحالات وسجل العمليات ويُرسل إشعاراً للمعنيين.
- النسخة المعدلة تُنشئ «إصداراً» جديداً للبحث، ويُحتفظ بالملف السابق في سجل الإصدارات.

## العلامة المائية
النص الحرفي: **عمل الطالبة رهف إبراهيم والطالبة أسيل خالد** (معرّف في `src/lib/constants.ts` ← `WATERMARK_TEXT`).

| الموضع | التنفيذ |
|---|---|
| جميع صفحات النظام | طبقة خلفية ثابتة في منتصف منطقة المحتوى بشفافية منخفضة (`.app-watermark`)، خلف المحتوى و`pointer-events: none` فلا تعيق النقر أو القراءة |
| ملفات PDF المولّدة (بطاقة البحث، التقارير) | نص قطري خفيف يتكرر في كل صفحة |
| التقارير المطبوعة | نفس القالب في صفحة الطباعة + قواعد `@media print` |
| ملفات Excel | في ترويسة وتذييل الصفحات المطبوعة + سطر تحت عنوان التقرير |
| ملفات PDF المرفوعة عند التنزيل | ختم قطري شفاف بواسطة pdf-lib (لا يُعدَّل الملف الأصلي المخزن) |
| التحكم | إعدادات النظام ← «إظهار العلامة المائية في المخرجات» (**مفعّلة افتراضياً**) و«ختم ملفات PDF المرفوعة» |

## الأمان
- **كلمات المرور:** bcrypt بعامل 12، ولا تُعرض أو تُرجع إطلاقاً.
- **الجلسات:** رمز عشوائي 256-bit في Cookie من نوع `HttpOnly` + `SameSite=Lax` + `Secure` في الإنتاج؛ يُخزّن في قاعدة البيانات مُجزّأً (SHA-256 مع `SESSION_SECRET`)، مدة 12 ساعة، وتُلغى الجلسات عند تعطيل الحساب أو تغيير كلمة مروره من الإدارة.
- **محاولات الدخول:** قفل الحساب 15 دقيقة بعد 5 محاولات فاشلة + حد لكل عنوان IP، وتسجيلها في سجل العمليات.
- **SQL Injection:** جميع الاستعلامات عبر Prisma (استعلامات مُعلَّمة).
- **XSS:** React يهرّب المخرجات تلقائياً، ولا يُستخدم `dangerouslySetInnerHTML`؛ قوالب PDF تهرّب كل القيم بالدالة `esc()`.
- **CSRF:** Server Actions في Next.js تتحقق من تطابق Origin/Host، والكوكيز `SameSite=Lax`، وواجهات API لتنزيل الملفات للقراءة فقط.
- **التحقق من المدخلات:** مخططات Zod لكل نموذج على الخادم.
- **الملفات:** حد أقصى للحجم (قابل للضبط)، قائمة امتدادات مسموحة، **فحص التوقيع الحقيقي للملف** (magic bytes) ورفض أي ملف لا يطابق امتداده، أسماء تخزين عشوائية (UUID)، تخزين خارج المجلد العام، الوصول فقط عبر `/api/files/[id]` بعد التحقق من الصلاحية، ورؤوس `nosniff` و`no-store`.
- **رؤوس الأمان:** `X-Frame-Options`، `X-Content-Type-Options`، `Referrer-Policy`، `Permissions-Policy`.
- **الأسرار:** في متغيرات البيئة فقط (`.env` مستبعد من Git).
- **سجل العمليات:** الدخول والخروج، الإنشاء والتعديل والحذف، تغيير الحالات، رفع وتنزيل الملفات، التحكيم، التصدير، الإعدادات، الصلاحيات، النسخ الاحتياطي.

## النسخ الاحتياطي
- **من الواجهة:** إعدادات النظام ← «إنشاء نسخة الآن» (يتطلب `pg_dump`)، مع قائمة بالنسخ وتنزيلها.
- **من سطر الأوامر / cron:** `npm run db:backup` ينشئ نسخة لقاعدة البيانات (`.dump`) وأرشيفاً للملفات المرفوعة (`.tar.gz`) ويحتفظ بآخر 30 نسخة.
  ```
  # مثال cron يومي الساعة 2 فجراً
  0 2 * * * cd /path/to/research-office && npm run db:backup
  ```
- **الاستعادة:** `pg_restore --clean --no-owner -d "postgresql://..." storage/backups/backup-XXXX.dump` ثم فك أرشيف الملفات داخل `STORAGE_DIR`.

## النشر على الإنترنت
متطلبات النشر:
1. **خادم Node.js 20.9+** (VPS أو خدمة تدعم تشغيل `next start` بشكل دائم، مثل PM2 أو systemd أو Docker). لا يُنصح بالاستضافات الخادمية (Serverless) لأن النظام يخزن الملفات على القرص ويشغّل Chromium.
2. **قاعدة PostgreSQL مُدارة أو مستقلة** مع نسخ احتياطي دوري.
3. **تخزين دائم** للمجلد `STORAGE_DIR` (قرص أو Volume دائم) — لا تضعه داخل مجلد المشروع إذا كان يُستبدل عند كل نشر.
4. **HTTPS إلزامي** عبر Nginx/Caddy كوكيل عكسي (Reverse Proxy). مع إعداد `client_max_body_size 60m;` في Nginx لرفع الملفات.
5. **Chromium** على الخادم لتصدير PDF: `npx playwright install --with-deps chromium` أو تثبيته من مدير الحزم وضبط `CHROMIUM_PATH`.
6. **متغيرات البيئة:** `DATABASE_URL`، `SESSION_SECRET` (قوي وعشوائي)، `CRON_SECRET`، `STORAGE_DIR`، `NODE_ENV=production`.
7. **خطوات النشر:**
   ```bash
   npm ci
   npm run db:migrate
   npm run db:seed:base        # أول مرة فقط (مع ADMIN_EMAIL و ADMIN_PASSWORD)
   npm run build
   npm start                   # أو: pm2 start npm --name research-office -- start
   ```
8. **مهمة مجدولة** (اختيارية) لتنبيهات المواعيد ونسخ احتياطي يومي:
   ```
   0 * * * * curl -s -H "Authorization: Bearer $CRON_SECRET" https://your-domain/api/cron/deadlines
   ```

## القرارات التقنية
- **Next.js 16 بدون Cache Components:** جميع الصفحات ديناميكية لأنها تعتمد على جلسة المستخدم وصلاحياته؛ هذا أبسط وأضمن لعدم تسريب بيانات عبر التخزين المؤقت.
- **Server Actions بدلاً من REST للعمليات:** تحقق موحد، حماية CSRF مدمجة، وأنواع مشتركة. واجهات API مخصصة فقط للتنزيل والتصدير.
- **مصادقة مخصصة بجلسات في قاعدة البيانات** بدلاً من JWT: إمكانية إنهاء الجلسات فوراً عند تعطيل الحساب.
- **Prisma 7 مع محوّل pg:** أحدث إصدار مستقر؛ إعداد الاتصال في `prisma.config.ts`.
- **Chromium لتوليد PDF:** المكتبات البديلة (jsPDF، pdfmake، react-pdf) لا تدعم تشكيل الحروف العربية واتجاه RTL بشكل موثوق. عند عدم توفر Chromium يعرض النظام صفحة طباعة جاهزة يمكن حفظها كـ PDF من المتصفح (مع العلامة المائية).
- **ختم PDF مسبق التوليد** (`assets/watermark-stamp.pdf`): يُضمَّن النص العربي مشكَّلاً بشكل صحيح دون الحاجة إلى Chromium عند كل تنزيل.
- **مكونات shadcn/ui مكتوبة داخل المشروع** (`src/components/ui`) بنفس أسلوب shadcn (Radix + cva + tailwind-merge) — وهي فلسفة shadcn أصلاً (نسخ المكونات إلى المشروع).
- **الخط مستضاف محلياً** (‎@fontsource/cairo) ليعمل النظام والتصدير دون اتصال بالإنترنت.
- **جولات التقديم والإصدارات:** `ResearchVersion` تمثل جولة تقديم (الأولى، ثم كل نسخة معدلة)، و`ResearchFile` يحتفظ بسلسلة الاستبدال (`replacesId` + `isCurrent`).
